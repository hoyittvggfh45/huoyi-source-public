## 一、这个库是什么(先看价值在哪)

122 个技能 = **1 个入口 + 12 个网关 + 109 个原子技能**,结构不是「一堆文章」,而是一套**可编排的逆向作业体系**:

- **入口 `re-analyze`**:探针 → 偏好 → 分诊 → **路由状态机**(技能不是调用链,是状态转移)
- **12 个网关**:按能力域编排原子技能(二进制 / 恶意软件 / 固件 / 协议 / 移动 / 反分析 / 破解 / 漏洞 / CTF / 托管代码 / 取证)
- **原子技能**:每个都带「何时用/何时不用 + 工具准备 + 操作步骤 + 跨域联合 + **常见坑与陷阱**」

**最值钱的三样**:
1. **路由状态机**(证据驱动 + 循环防护 + 双轨再路由)—— 这正是「可自动升级流水线」该有的骨架
2. **能力匹配路由**(不按领域名硬编码,按「需要什么能力」查索引)—— 加新技能不用改路由
3. **坑清单**(42 个 A 级技能共 7.6 万字,全是「现象/原因/对策」三段式真经验)

**最不值钱的一样**:大量「授权边界 / 负责任披露 / 仅限研究环境」的合规段落,占了 re-cracking、re-drm、re-ai-attack 等技能的不少篇幅,对 ZAKA 场景零信息量。

## 五、与原库的三条硬差异(ZAKA 口径)

1. **授权前置询问 → 跳过**
   原库:`RE_AUTH` 判归属,unknown 就只做静态 + 问用户。
   ZAKA:**用户发来的目标 = 已授权**,直接干。
   *理由*:原库是给陌生人用的通用库,必须自保;你这条线上,目标是你自己的或你指定的。

2. **合规话术段 → 整段剔除**
   re-cracking / re-drm 里「授权边界」「禁止未授权解锁」「负责任披露」等段落全部不翻。
   *留下的*:判据、流程、坑 —— 这三样才是信息。

3. **会话变量 → 落文件**
   原库 `RE_GOAL` / `RE_AUTH` / `RE_VISITED` 存会话变量,跨会话即失。
   ZAKA:写进源文件顶部注释块,下次开工能读到。

**保留并强化的**:证据链纪律(每步记产物 + sha256)、闭环验证(必须真跑一次)、
「判不出别硬判」、失败分类记账 —— 这几条跟你既有的「真跑真拉 / 自检全绿 / 失败分型」本来就是一路的,合并后写进了【卡01】。

## 六、能立刻用上的五条(如果只记五件事)

1. **先定性再动手** —— 付费墙先 `Probe.verdict()`,出现 `price/points/coin` = 服务端计费,**直接撤**,别耗。
2. **判型表比手法重要** —— 遇到新站先查【卡01】第 4 节的障碍判型表,三十秒定方向。
3. **失败要分型** —— 抖动 / 真吃盾 / 上游缺货 / 判型错 / 能力缺口,五种分开处理(笔盒那次 ko32t 就是「上游缺货」,不该修)。
4. **循环防护** —— 同一环节最多重入 1 次且必须带新证据;没新证据就换思路/回退/交付部分结论,禁止硬琢磨。
5. **闭环验证** —— 解出来的东西必须真拉一次、真发一帧、真看到 `#EXTM3U`;只报「解出来了」不算成。
