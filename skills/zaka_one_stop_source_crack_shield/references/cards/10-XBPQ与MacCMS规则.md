## 一、定位与选路

XBPQ 是 jar 爬虫 `csp_XBPQ` 驱动的**声明式 JSON 规则**：不写代码，只填字段——每个字段是一段「前锚 `&&` 后锚」的字符串截取规则，壳负责取页、截取、组装成 TVBox 的分类/列表/详情/播放。

- **什么时候直接交 XBPQ 规则**：目标是明文 HTML 站（MacCMS 占绝大多数），且用户的壳带 XBPQ jar。零代码、最快交付，改版只改锚点。
- **什么时候把 XBPQ 当情报用**：用户的壳是 Python 壳（如 FongMi py）或自有 jar 没有 XBPQ 时，规则本身就是一份现成的站点测绘——分类表、分类url 模板、筛选结构、详情锚点、播放锚点全在里面，照第五节翻译表转成 Python 蜘蛛即可。**摸 MacCMS 站之前先查规则库里有没有同站现成 XBPQ**（gao-xBPQ 目录、he883 聚合配置），与「写源先查 ZakaTV jar 有无同站配方」同理。
- **什么时候别用 XBPQ**：站点走 API、响应加密/签名、有盾、播放要多步换链——声明式截取撑不住，回到主流水线写 py。硬套只会浪费时间。

## 二、字段全表（按已核对规则的实际出现整理）

### 站点与请求

| 字段 | 含义 |
|---|---|
| 站名 / 作者 | 规则的显示名与署名（聚合配置里另有站点条目的 key/name/api=csp_XBPQ/ext 指向规则） |
| 主页url | 站点根地址，相对截取与图片补全的基准 |
| 请求头 | 请求头预设（如「手机」一类 UA 预设名，以壳实现为准） |
| 编码 | 页面编码（EasyTVbox 规则中出现，如 utf-8/gbk） |

### 分类与筛选

| 字段 | 含义 |
|---|---|
| 分类 | 分类表，两种写法见第四节 |
| 分类值 | 与「分类」按 `&` 位置一一对应的分类取值/路径片段（写法 B 专用） |
| 分类url | 分类页 URL 模板，含占位符 `{cateId}` `{catePg}` `{area}` `{by}` `{class}` `{lang}` `{letter}` `{year}` |
| 筛选 | 按分类 id 分组的对象：键是分类值（如 `"1"` `"2"` `"4"`），值是一组 `{key, value}`，其中 key 是分类url 里的占位符名（catePg/class/area/year/by 等），value 是 `{"n": 显示名, "v": URL片段}` 的列表 |

### 列表（分类页与首页共用）

| 字段 | 含义 |
|---|---|
| 数组 | 列表条目的截取范围（先圈条目块，再在块内取下面四项） |
| 图片 | 条目内封面图截取 |
| 标题 | 条目内标题截取 |
| 链接 | 条目内详情链接截取 |
| 副标题 | 条目内副标题截取（备注/集数/评分一类） |

### 搜索

| 字段 | 含义 |
|---|---|
| 搜索模式 | 搜索走法开关：`1` = 用下面的 搜索url 自定义地址；`0` = 走默认搜索、只给 搜索后缀（此条为多份规则对照后的归纳，交付前实测确认） |
| 搜索url | 自定义搜索页模板，占位符 `{wd}`（关键词）`{pg}`（页码） |
| 搜索前缀 / 搜索后缀 | 旧式写法：前缀+关键词+后缀拼搜索请求；详情链接后缀也常见单独给（如 `/voddetail/`） |
| 搜索数组 / 搜索图片 / 搜索标题 / 搜索链接 / 搜索副标题 | 与列表五件套同构，作用于搜索结果页（搜索结果结构与分类页一致时可省，见第六节 MacCMS 固定搜索） |

### 详情

| 字段 | 含义 |
|---|---|
| 影片年代 / 影片地区 / 影片类型 / 影片状态 | 详情页对应信息项的截取 |
| 导演 / 主演 | 详情页演职员截取 |
| 简介 / 剧情 | 剧情简介截取（两名在不同规则中都出现过，以壳实现为准） |

### 播放

| 字段 | 含义 |
|---|---|
| 线路数组 / 线路标题 | 播放线路（播放源分组）的截取范围与线路名 |
| 播放数组 | 集数列表的截取范围 |
| 播放列表 / 播放标题 / 播放链接 | 集数项内的分集名与播放页地址截取（EasyTVbox 规则中出现） |
| 过滤词 | 播放/嗅探时过滤掉的词（issue #158 标注规则中出现） |
| 排序 | 播放列表排序相关（EasyTVbox 规则中出现） |

## 三、语法三件套

1. **截取语法 `前锚&&后锚`**：取页面中前锚之后、后锚之前的内容；这是 XBPQ 的本体，不是 XPath、也不是 CSS 选择器。锚点要选**结构性、页面内稳定的文本片段**（标签+属性碎片最常用），例：七七影视的简介写成 `detail-content" style=*>&&</span>`——锚里直接带属性碎片和 `*` 通配。
2. **修饰语法 `[替换:旧>>新]`**：接在字段值后面做字符串替换清洗。555电影的线路标题用它剥标签注修饰：`[替换:</span><small>>>👉]` 一类写法，把原始 HTML 碎片替换成展示符号。标题/副标题清洗同理。
3. **URL 占位符**：分类url 用 `{cateId}`（分类值）`{catePg}`（分类页码）`{area}` `{by}`（排序）`{class}`（类型）`{lang}` `{letter}` `{year}`；搜索url 用 `{wd}` `{pg}`。**铁律：`fyclass`/`fypage`/`**` 是 JS 爬虫规则（`var rule = {...}` 那套）的占位符，XBPQ 里从来不出现，混写必挂**——已核对的全部 XBPQ 规则无一例外。

## 四、分类的两种写法（最容易写错处）

**写法 A · 名称$id 串（主流）**
- `分类` 写成 `电影$1#电视剧$2#综艺$3#动漫$4`：`#` 分条、`$` 左边是显示名、右边是分类值。
- `分类url` 里用 `{cateId}` 接分类值，如奈飞影视：`https://www.naifei.im/vod/show/{cateId}-{area}-{by}-{class}-{lang}----{catePg}---{year}.html`。

**写法 B · 名称串 + 分类值串按位对应**
- `分类` 写成 `Netflix&电影&连续剧&动漫&综艺记录`，`分类值` 写成 `/label/netflix&/vodtype/1&/vodtype/2&/vodtype/4&/vodtype/3`：两串用 `&` 分段、**按位置一一对应**，错位一格全站分类全错。
- 此时分类值是**整段路径片段**，`分类url` 如 `https://zhenfanjixie.com{cateId}/page/{catePg}.html`，`{cateId}` 直接展开成 `/vodtype/1` 这类路径。

筛选与分类url 的关系：筛选里每个 `{key, value}` 的 key 必须与分类url 中的占位符**同名**，用户在壳里选了某个筛选项，壳就把对应的 `v` 填进同名占位符；名字对不上，筛选点了没反应且不报错。

## 五、从 XBPQ 翻译到 Python 蜘蛛（字段对照）

| XBPQ 侧 | Python 蜘蛛侧 |
|---|---|
| 主页url + 分类 + 分类url + 筛选 | `homeContent` 的 class 列表 + `categoryContent` 的 filters（筛选的 n/v 直接转壳的 filter 结构） |
| 数组 / 图片 / 标题 / 链接 / 副标题 | `categoryContent` 的列表解析：数组锚定条目块，其余四项在块内截取或等价选择器 |
| 影片年代/地区/类型、导演/主演、简介 | `detailContent` 的 vod_year/vod_area/vod_class、vod_director/vod_actor、vod_content |
| 线路数组/线路标题 + 播放数组/列表/标题/链接 | `detailContent` 的 vod_play_from（线路名 `$` 分隔组）与 vod_play_url（集名 `$` 地址、`#` 分集） |
| 搜索url / 搜索五件套 | `searchContent`：搜索url 模板转请求，搜索数组等转结果解析 |
| 播放链接指向播放页、壳内嗅探 | `playerContent` 回播放页现取真实地址（MacCMS 播放页的地址常有时效/解析依赖，照主流水线的现取原则） |

反向同理且为硬性规范（用户 2026-10-23 定）：**py 与 XBPQ 规则文件同时落地、同时推送**——每单 py 源交付时，必须用同一份摸站成果把锚点与 URL 模板回填成一份 XBPQ 规则（文件名 `<站点key>_xbpq.json`）一并交付推送，不再只是 MacCMS 站的附赠。站点属 API/加密/过盾等声明式截取根本撑不住的形态时，规则只写它能诚实承载的部分，并在使用说明里注明其边界，不许编造跑不通的字段充数。

## 六、MacCMS（苹果CMS）专章

- **判型**：URL 出现 `/index.php/vod/show|search|detail|play/...` 或伪静态 `/vod/show/...`、`/vodtype/N`、`/voddetail/`，详情页有 MacCMS 模板痕迹，即按 MacCMS 处理。分类url 的段位顺序以该站模板为准，实测三种真实形态：
  - `/vod/show/{cateId}-{area}-{by}-{class}-{lang}----{catePg}---{year}.html`（奈飞影视，`show` 后多段横线占位）
  - `/index.php/vod/show{area}{by}{class}/id/{cateId}/page/{catePg}{year}.html`（APP影视，筛选值是带斜杠的片段、直接拼进路径）
  - `/show/{cateId}-{area}--{class}-----{catePg}---{year}.html`（七七影视，v10 伪静态）
  段数与横线数**逐站不同、不可照抄**，必须以该站分类页真实链接为准。
- **搜索基本是固定的**（he883 聚合配置里的原注释即明说：现在网站基本都是苹果CMS，搜索部分基本不用动）：
  - 建议接口：`/index.php/ajax/suggest?mid=1&wd={wd}&limit=500`（旧式规则的搜索前缀/后缀就是拆开写它）；
  - 分页搜索页：`/index.php/vod/search/page/{pg}/wd/{wd}.html`，配 `搜索模式=1` + 自定义 搜索url；
  - 模板差异警告：个别模板的搜索分页走路径段位编码（如本库 AiPorn 单实测的 14 段路径式搜索），翻译成 py 或改规则前先实测该站搜索的翻页形态，不要默认 suggest 接口万能。
- **详情与播放**：详情链接后缀常见 `/voddetail/`；播放数据在播放页（MacCMS 的 player 数据结构），XBPQ 靠播放数组锚集数列表、壳内嗅探出流；若该站播放必须走解析接口或地址有时效签名，XBPQ 只能到播放页为止，最终出流靠壳的解析配置或改走 py 源现取。

## 七、验证（规则没有 shellsim，照全量自检门人工过）

规则交付前在目标壳里逐项验，与 py 源同一标准：每个一级分类首页非空且有真封面、翻页可用、每组筛选至少抽一个组合能出结果、搜索出真结果、详情字段（年代/地区/类型/导演/主演/简介）不串位、线路与集数完整、点播能出流。锚点失效的典型症状是「整类空白」或「字段串位」，先查数组锚是否还圈得住条目块，再查各项锚。
