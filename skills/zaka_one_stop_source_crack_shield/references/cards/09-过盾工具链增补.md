## 一、五路分层与默认升级梯子

社区共识已收敛为五类路线。写源场景按成本从低到高逐档升，**低档能过就不用高档**：

### 第 1 档 · 纯 HTTP 指纹伪装（无 JS 执行，先试它）

- **curl_cffi**（lexiforest/curl_cffi，6,758★，极活跃）：Ares curl 段的本体。`impersonate=` 一参切换 TLS/JA3 + HTTP/2 指纹，API 与 requests 兼容。
  - **画像必须随浏览器版本滚动**：0.17 版已到 Chrome 151/152、Safari 27、Firefox 153–155；Ares 现用的 `chrome_120` 已是旧画像，旧画像本身就是特征——升级 Ares 时先换画像串。
  - 支持 HTTP/3 指纹、每请求代理轮换；同门 brimp（带 JS 引擎的轻量版）是撞上轻量 JS 挑战时的中间档。
- **httpcloak**（sardanioss/httpcloak，1,349★，新仓上升中）：全协议栈伪装最全：JA3/JA4 + GREASE 随机化 + 后量子密钥交换 X25519MLKEM768 + ECH 加密 SNI + HTTP/2 帧级参数 + TCP/IP 栈（TTL/MSS/窗口）。`httpcloak.get(url, preset="chrome-latest")` 一行。有 **Android（Kotlin/AAR）绑定**，对 Termux 落点有额外价值。现代盾查的多是 UA 之外的这些层。
- **surf**（enetx/surf，1,845★）：Go 栈的 JA3/JA4 + HTTP/3 客户端，Go 工具链场景选它。

适用：只在指纹层设卡、无 JS 挑战的盾。对 TVBox 写源最友好（可直接进蜘蛛的请求层）。

### 第 2 档 · 引擎级反检测浏览器（需要真浏览器跑挑战链时）

2025–2026 年最明确的转向：**指纹伪造从 JS 注入层下沉到浏览器 C++ 引擎层**；JS 注入式 stealth 已被社区判定「有接缝、必被检」。

- **Camoufox**（daijro/camoufox，12,706★，极活跃）：魔改 Firefox，navigator/screen/WebGL/字体/音频/WebRTC 全部由引擎原生回答，无 override 接缝。**新浏览器档的默认引擎，替代 undetected 系**。
  - 身份要**内部一致**：从真实设备分布抽整套身份（UA/屏幕/GPU/字体互相匹配），内置 coherence 校验拒绝不存在的组合——乱拼指纹反而是破绽。
  - 挂代理开 `geoip=True`：时区、locale、地理、WebRTC IP 自动与出口 IP 对齐。
  - Juggler 隔离世界驱动，自动化对页面不可见；`NewContext()` 单浏览器多身份。
- **invisible_playwright**（feder-cr，2,503★）：同路线 C++ 补丁 Firefox，强在**行为人类化**：自然鼠标轨迹 + 人类时序、输入事件字节级等同真实输入。Turnstile/reCAPTCHA 打行为分，只过指纹不过行为照样卡。API 与原生 Playwright 兼容；另有 MCP 版（874★）。
- **patchright**（Kaliiiiiiiiii-Vinyzu，4,935★）：不换浏览器，先修 Playwright 驱动层泄漏（如 CDP Runtime.enable）。已有 Playwright 流水线时升级成本最低；也是社区 Turnstile 求解器的主流底座。
- **nodriver**（ultrafunkamsterdam，4,880★）：undetected-chromedriver 的官方继任者，异步 CDP 直连。老 uc 方案迁移看它。
- **DrissionPage**（g1879，12,530★，国产中文文档全）：浏览器模式与数据包模式同会话无缝切换、共享 cookie。**摸站姿势：浏览器只负责过盾/登录，拿到会话切数据包模式高速抓取**，比全程浏览器快一个数量级；国内站点/国产盾适配经验多。

### 第 3 档 · clearance 求解服务化（长期、批量、生产场景）

浏览器退居「解题机」，业务走普通 HTTP 复用 cf_clearance——与 Ares「开发机解题、cookie 固化」同构，服务化是它的规模化形态。

- **FlareSolverr**（15,998★，活跃）：基准方案。Selenium + undetected-chromedriver 解题，回吐 HTML + 全套 cookies；8191 端口 cmd 协议（`request.get` / `sessions.create`）已成事实标准。常驻 session 摊薄启动成本，用完显式关闭防泄漏；**本机内存吃紧时禁止并发猛打**（每请求新建浏览器实例）。
- **trawl**（germondai/trawl，1,043★，2026 新仓）：现代替代者。核心是**分层降级 + clearance 缓存**：先 HTTP → 复用已验证 clearance → 真需要才拉 Camoufox；兼容 FlareSolverr `/v1` 接口可平替；盾型覆盖 CF/Anubis/Akamai/Imperva/DDoS-Guard/AWS WAF/DataDome；API + MCP + 转发代理三形态。
- **Boterdrop-Solver**（najibyahya，209★）：FastAPI + Camoufox 四合一 solver 范本：按盾型拆端点（`/turnstile`、`/clearance`、`/aws-token`、`/recaptchaV3`）；每实例独立代理轮换；**无头跑不动时用 xvfb 有头模式**（不少盾对纯 headless 更严）；定时强制内存回收适合低配机。
- **CloudflareBypassForScraping**（sarperavci，2,625★，已 2.0）：整请求镜像代打：客户端带 `x-hostname` 头把任意方法请求交给已过盾的浏览器会话代发并镜像回结果。**只要 cookie 用 FlareSolverr 系；要连 POST 接口一起代打用这个**——对应「壳/源本身完全碰不了盾、必须外挂网关」的形态。

### 第 4 档 · Turnstile 专项求解

- 底座选 patchright 系：Theyka/Turnstile-Solver（954★）是现成实现（patchright 多线程 + API 化）。
- 付费打码 API（2captcha 等）只作兜底。token 与**站点 + UA + 出口 IP** 绑定且时效短——求解与业务必须同出口同 UA（见第三节铁律）。

### 第 5 档 · 纯请求协议逆向求解（只作情报）

- 完全不用浏览器、纯请求复现挑战协议的仓（如 munew/cloudflare-turnstile-solver 一类）：成本最低但最脆弱，CF 一更新即失效、仓库普遍短命。**只看思路，不作长期依赖。**
- 历史参照：cloudscraper（6,801★）对现代托管挑战已基本失效，不再融合。

## 二、摸站顺带工具

- **Scrapling**（D4Vinci，89,069★，极活跃）：三级 Fetcher 分层（普通伪装档 → StealthyFetcher 隐身浏览器档）与上面的梯子同构；`record_requests=True` 可后台捕获页面背后的 API 响应并事后检索——**摸站找真实接口时实用**；自带 ProxyRotator 与 DoH 防 DNS 泄漏。已有 Agent Skill 形态样板：Cedriccmh/claude-code-skill-scrapling（456★）的「盾型路由表 + 站点经验库」组织法可参照。

## 三、复用铁律（与坑总表互链）

1. **cf_clearance 复用 = 同 UA + 同 IP**：取 cookie 时的 UA 与出口 IP 必须与后续业务请求完全一致，否则 clearance 直接作废（CF-Clearance-Scraper README 明示；与 Ares 的 cookie 固化经验一致——固化时连 UA 一起固化）。
2. **Turnstile token 同理且更严**：站点、UA、出口 IP 三绑定，时效以分钟计；求解环境与业务环境分离时先对齐这两项再谈其他。
3. **IP 是天花板**：各大仓一致强调住宅/移动代理 + geoip 一致性（时区、语言、WebRTC、地理与出口 IP 对齐）；机房 IP 面对高等级托管挑战，再完美的指纹也救不回来，只能换出口——与 MissAV 单实测（机房出口全指纹 403、家庭出口可直连）完全互证。**判型时先确认出口等级，别在机房 IP 上反复调指纹。**
4. **指纹画像会过期**：impersonate 目标版本、UA、Client Hints 必须成套滚动更新；header 顺序、Sec-Fetch-*、Sec-Ch-UA 要与 UA 互相咬合。
5. **headless ≠ headed**：两边报告值不一致是经典检测点；纯无头通过率低时优先 xvfb 有头，不要先怀疑指纹。

## 四、与 CF-Ares 的衔接动作

- Ares curl 段：画像串从 `chrome_120` 升到当前 chrome 最新档，并把「画像版本」列入每次交付的检查项。
- Ares 浏览器段：引擎优先级改 Camoufox > patchright（已有 Playwright 时）> undetected（存量兼容）；行为敏感目标（Turnstile 托管挑战）加人类化轨迹。
- 长期批量目标：不再单机反复解题，按 FlareSolverr 协议外挂 trawl/FlareSolverr 服务（clearance 缓存复用），蜘蛛侧仍只吃固化 cookie，协议不变。
- 盾型超出 CF（Akamai/DataDome/Anubis 等）：trawl 的多盾覆盖是现成参照，Ares 的 detect_cf 判型需相应扩到多盾识别后再路由。
