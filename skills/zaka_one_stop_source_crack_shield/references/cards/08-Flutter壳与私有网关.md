# 卡08 · Flutter 壳与私有网关(「看起来能扒」但可能根本不该扒的那类)

> 来源:2026-10 AvBox 实战(34.7 MB Flutter 聚合壳,32 站 / 93 路由 / 23 台网关节点)
> 配套:`tools/flutter_triage.py`(判壳+取数面)、`tools/gate_probe.py`(零区分度判定)
> 这张卡的价值不在"怎么破",而在**什么时候该停、停之前要把什么拿走**。

---

## 一、什么时候用(触发特征)

- 用户发来一个 apk:「逆向它,写个 py 插件 / 扒它的源」
- apk 里有 `lib/<abi>/libapp.so` + `libflutter.so` + `assets/flutter_assets/` → Flutter
- jadx 打开 java 层几乎是空壳,dex 数量 1~2 个,搜不到任何业务字符串
- 接口要求签名头(`X-Auth-*` / `sign` / `nonce` / `timestamp`),且**换什么组合都被拒**
- 回包是 `{"code":..,"msg":..,"data":"<base64>","capi":"1"}` → 还有一层响应体加密
- 本质是「聚合壳」:底下挂几十个源站,全走它自己的私有网关

一句话:**目标不是"一个站的接口",而是"一个壳 + 一道自己写的门"。**
门的钥匙编译进机器码里,不在 dex、不在明文配置、不在网络请求里。

---

## 二、第一步永远是判壳(2 分钟,别跳过)

```bash
python3 tools/flutter_triage.py app.apk --json case.json --dump-dir case/
```

一次给出:引擎(flutter / rn-hermes / webview / packed / native)、路由数、域名池、
模块名、认证头名、疑似密钥。**这些是后面无论走哪条路都要用到的东西,先落盘。**

判壳结论直接决定分岔:

| 引擎 | 走法 |
|---|---|
| flutter | 静态面(字符串/对象池)先扒;算法拿不到才上反汇编 |
| rn-hermes | hbc-decompiler / hasm,别啃 so |
| webview / uni-app | 业务在前端层,走卡03 |
| packed | 先脱壳,走卡05 |

## 三、三层阶梯:先算「这活要几小时、几天,还是根本不该干」

```
L1 静态面(分钟级)
   libapp.so 里的可打印字符串 → 域名池 / 路由 / 头名 / 硬编码 key / Dart 源文件路径
   ↓ 拿到了接口形态,但签名算法不在明文里
L2 反汇编(小时~天级)
   blutter → asm/ 里搜签名函数符号 → 读拼接顺序 → 翻译成 Python
   ↓ 环境不够 / 时间不够 / 破了也没有可播源
L3 动态(准,但要真机)
   Frida hook 签名函数的返回值 → 直接拿它算好的 sign,连算法都不用还原
```

**判据(别自我感动)**:

- L1 能出数据 → 收工,别往下走。
- L1 只出形态、签名在快照里 → 先做**第四节的零区分度判定**,再决定要不要上 L2。
- 零区分度 + 环境不够 → **这条线在当前条件不成立**,写档案、交资产、给下一步。别硬啃。

## 四、零区分度判定(这张卡最值钱的一条)

**规则:先看「试错能不能得到反馈」,再决定要不要穷举。**

```bash
python3 tools/gate_probe.py --base https://api.example.com \
        --path /module/x/search --param wd=test
```

它打一组语义等价的变体(裸请求 / 根路径 / 不存在路径 / 假 key / 假签名头 / 换方法 / 换 UA),
按**报文指纹**聚类,给三种结论:

| 结论 | 含义 | 该干什么 |
|---|---|---|
| `differentiated` | 缺哪个参数就提示哪个 | **值得试错**,逐字段补,最后才穷举排序 |
| `weak` | 只有「通用错误 vs 正常路径」两种 | 只能探"路径存在性",反推不了签名 |
| `zero` | 所有请求同一条报文 | **立刻停止穷举**,转算法提取 |

**零区分度意味着什么**:签名空间再大也只是"猜",没有梯度就没有收敛。
这时候发 460 种拼法、换 5 种摘要、试 2 种位置 —— 全部是无信息量的重复劳动。
**它不是"再试试",是硬判据。**

> 实证:AvBox 的 23 台网关节点对任何未过签请求一律回 `{"code":400,"msg":"违规请求"}`,
> 连根路径 `/` 也一样。460 种组合全打在这同一条报文的墙上 —— 那 460 次从一开始就没有意义。

## 五、环境门槛预检(上 L2 之前必须做,不然白烧一轮)

blutter / 任何"本地拉源码再编译"的工具,先量四个数:

```bash
cat /sys/fs/cgroup/memory.max                     # cgroup v2 真实限额
cat /sys/fs/cgroup/memory/memory.limit_in_bytes   # cgroup v1
free -m | awk 'NR==2{print $7}'                   # available(MB)
nproc
```

| 项 | 判据 |
|---|---|
| 内存限额 | 编译反汇编组件 **2G 起步**,并行编译留 **8G**;**看 cgroup 限额,不是机器总内存** |
| 剩余时间 | 11 MB 的 libapp.so 反汇编不是分钟级 |
| 磁盘 | 拉 Dart SDK 源码 + 产物,按 GB 留 |
| 出口 | 能否下载对应版本 Dart SDK |

**限额 < 需求 → 直接判"当前环境不成立"**,写进档案,给替代路径(见第六节)。
**不要开跑再说"内存爆了"** —— 跑一半被打死,用户白等一轮,比不开更亏。

> 实证:那次 blutter 就是死在本地编译那步的峰值内存,任务被打成内存超限。
> 根因不是工具不行,是**开跑前没算这笔账**。

## 六、撤退判据:破开了 / 破不开,都要交东西

### 破不开时,照样有可交付资产(这部分最容易被忽略)

1. **逆向档案**:包体结构、引擎判定、模块清单、路由全集、网关节点、签名头形态、
   已排除的方向(哪些试过、为什么排除)—— 下一次接手的自己不用重跑一遍。
2. **可插拔骨架**:把"算签名"抽成一个函数 `make_sign(...)`,其余(路由/参数/解析)全写好。
   算法一到手,填进去就能通吃。
3. **原始数据**:`routes.json` / `mods.json`(直接能进索引、能当测试集)。
4. **明确的下一步**:用什么工具、在哪台机器、拿到什么之后怎么接。
   「找台 8G 以上的机器跑 blutter,把 `_generateSign` 那段 asm 发我」——
   这是可执行的下一步,不是"再研究研究"。

### 还有一个更狠的撤退理由:**破了也没用**

先问一句:**破开之后,能拿到 TVBox 播得动的东西吗?**

> 实证:AvBox 底下 32 个站全在私有网关后面;明文里唯一直连的真源站只有 missav / javdb。
> missav 三家域(missav.ws 403、missav.com 退化跳转、missav.tv 广告壳)都不给内容;
> javdb 是元数据站,只给磁力,TVBox 播不了磁力。
> **也就是说:就算把签名破开,也没有能直接接进 TVBox 的源。**

这条要在动手前就想清楚 —— **技术上能破 ≠ 破完有用**。
把"破完没用"的判断提前说,比啃了三天再说"其实没源"值钱得多。

### 破开之后的交付形态(一次通吃)

聚合壳的模块各自实现一份拦截器(`module/<站名>/network/interceptor.dart`)——
**签名逻辑是复制粘贴到各模块的,破一处基本等于全破**。
所以最优交付不是"给某个站写一个源",而是:

- 一个**通吃版 py 源**,站名当参数切(`ext: {"site":"javdb"}`)
- 路由表从 `routes.json` 驱动,新增站点只加数据不改代码
- 签名函数独立成模块,过期了只改它

---

## 七、这条线的纪律

1. **别把"能扒"当成"该扒"**:先算投入产出,再动手。
2. **别把"试错"当方法**:没有区分度的目标,试错不是进度,是自我安慰。
3. **别把"破不开"当失败**:档案 + 骨架 + 数据 + 下一步,是完整交付。
4. **别在被打死之后再解释**:环境门槛在开跑前算,不在崩了之后说。
5. **别编**:没破开就说没破开;JVM 起不来说起不来;不给假成功。
