# 卡03 · 前端层逆向(JS 混淆 / SPA 取数 / WASM)

> 来源:`library/re-script-deob`、`re-deobfuscate`、`re-browser-ext`、`re-electron`、
> `re-wasm`、`re-java`(前端也有 Java 系)、`re-managed` 网关

---

## 一、什么时候用

- 站点是 SPA(Vue/React/Nuxt/Next),**F12 里 JS 打散成一堆短变量名**、看不到业务逻辑
- 逻辑明显在前端但**读不出来**(`_0x` 变量、大数组索引、控制流平坦化)
- 逻辑被编进 **WASM**(`.wasm` 文件,或 JS 里 `WebAssembly.instantiateStreaming`)
- 需要**复刻前端某个算法**(签名、加密、参数拼装)到 Java/Python
- 要扒**浏览器扩展**的行为(扩展里带密钥/接口)

## 二、JS 混淆还原(阶梯,从最省事开始)

### 第 0 级 · 先别解,**先取数**

大多数站根本不需要还原算法:数据已经在网络层了。

```bash
# ① 内嵌数据优先吃(省掉整条还原链)
#    __NEXT_DATA__ / __NUXT__ / RSC Flight / window.__INITIAL_STATE__
#    → ZakaCrackKit.Page 直接取
# ② 接口直接打(带对 headers 就能拿)
# ③ 真要算法(签名/解密)才往下走
```

> **判据**:能从 `__NEXT_DATA__` 或接口直接拿到数据 → 停在这里,别去解混淆。这是最省时间的一步。

### 第 1 级 · 格式化 + 常量还原

```bash
# 格式化
npx js-beautify bundle.js > bundle.pretty.js

# 纯编码层(最常见,直接解)
# base64 / hex(\xHH) / charCode(atob / String.fromCharCode) / unescape
```

浏览器控制台直接验:

```js
// 把可疑的那段贴进去,把 eval/Function 换成 console.log 看它要执行什么
// 数组索引式混淆:_0x1234[0] → 手工把数组摊出来对照
```

### 第 2 级 · 字符串表 + 索引混淆(`_0x` 类)

ZAKA 已有现成件:

```python
from zaka_crack_kit import Obf
# Obf:_0x 混淆还原 / 挖密钥 / 挖接口
```

手工路子(有效且通用):
1. 找到那个大字符串数组(通常在文件头部)
2. 找到取值函数(索引经过位移/异或/反转的那个)
3. 写个小脚本**批量替换**:把 `_0xabc(0x1f)` 全部换成字面量
4. 替换完再 beautify,业务逻辑就露出来了

### 第 3 级 · 控制流平坦化

特征:**大量基本块都收敛到一个 dispatcher switch**,状态变量在每块尾部被改写。

- 前端工具:`de4js` / `webcrack` / `Babel` 系列插件
- 手工:定位 dispatcher 的 switch 变量 → 跟踪它的写入点 → 按状态值连线还原原始顺序
- **状态变量找错是最大风险** —— 先用自动化工具,手工时先确认变量真的参与 dispatcher 索引

### 第 4 级 · 看不懂就动态跑

静态解不出来时的万能办法:**让浏览器自己跑,你在关键位置断点**。

- F12 Sources → 给可疑函数打 breakpoint → 看**入参和返回值**(拿签名/密钥最直接的方式)
- `XMLHttpRequest.prototype.send` / `fetch` 挂钩打印请求体
- 这就是「JS 插桩」:找加密前的明文 `plain`,逐个字段查来源
- **核心原则:输入完全一致,而不是算法等价** —— 明文对上了,加密反而是最简单的一步

## 三、SPA 取数速查

| 框架 | 数据藏在哪 | 怎么取 |
|---|---|---|
| Next.js (App Router) | RSC Flight 载荷 / `self.__next_f` | `Page` 模块直接吃;或打 `?_rsc=` 接口 |
| Next.js (Pages) | `__NEXT_DATA__` script 标签 | 正则抠 JSON |
| Nuxt | `window.__NUXT__` | 同上 |
| Vue SPA | 无内嵌 → 真数据在接口 | 抓包定接口(卡02 第 1 步) |
| React SPA | 同上 | 同上 |
| 任意站 + API 网关 | 接口域常与页面域不同 | 搜 bundle 里的 `baseURL` / `api.` |

**框架指纹**:`ZakaCrackKit.Page` 里有 `__NEXT_DATA__` / `__NUXT__` / RSC Flight 三个解析器,先用它。

## 四、WASM 分支

```bash
# 拿到 .wasm 后
wasm2wat module.wasm > module.wat      # 反汇编成可读文本(WABT)
wasm-decompile module.wasm             # 反编译成类 C 伪码
```

要点:
- WASM 里常放**加密/签名算法**(前端不想暴露源码)
- 导出函数表(`.wat` 里的 `(export ...)`)是入口清单,先看导出了什么
- **数据段里的常量**要单独抠出来(字符串、密钥表常在 data 段)
- 逻辑太绕时别硬读:用 Node 直接**加载这个 wasm 调用它**(把 wasm 当黑盒用),比还原算法快

## 五、浏览器扩展 / Electron

**扩展**(`re-browser-ext`):
```bash
# .crx 就是 zip,直接解
unzip ext.crx -d ext/
# manifest.json → 权限、content_scripts、background、host_permissions
# background service worker 里常藏接口与密钥
```

**Electron**(`re-electron`):
```bash
npx asar extract app.asar app/         # asar 解开就是源码
# 主进程 main.js 里常有本地接口、token 逻辑
# 混淆的部分回上面第 1~4 级
```

## 六、常踩的坑

- **上来就解混淆,结果发现数据根本不用解** —— 先看网络层能不能直接拿(第 0 级)。
- **只解一层就以为完了** —— 混淆常是套娃:解完 base64 里面还是 `eval`,回到第 1 级重新识别。
- **`js-beautify` 之后还是读不懂** —— 那是字符串数组/平坦化,不是格式化问题,往上走级。
- **还原了算法但签名还是对不上** —— 检查:字段排序、时间戳单位(秒/毫秒)、大小写、是否 `encodeURIComponent` 过。
- **动态断点断在压缩过的代码里** —— 先格式化再断,或在 Sources 里用 Pretty print。
- **WASM 硬读** —— 多数情况当黑盒调用即可,别陷进指令级还原。
