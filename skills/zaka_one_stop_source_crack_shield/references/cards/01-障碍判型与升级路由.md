> 来源:`library/re-analyze`(唯一入口 + 路由状态机)、`references/triage.md`(任务识别决策表)、
> `references/rerouting.md`(双轨再路由)、`re-feedback`(经验反馈元网关)
> 这是整套库里**最值钱的一张** —— 它不是手法,是「什么时候用什么手法」的调度骨架。
> 爬渗线管「流程怎么走」,这张卡管「**判型怎么做、升级往哪升、什么时候回退**」。

---

## 一、这张卡解决什么

原库的核心设计是**状态机,不是调用链**:

```
triage(判型) → route(选路) → skill execution(执行) → evidence(证据) → route(再判) → 循环
```

关键差别:技能不是按顺序排好的流水线,而是**每一跳都靠上一步产出的新证据驱动**。
用户要的「可自动升级的流水线」,架构上就是这个形态。

## 二、ZAKA 版口径(与原库的差异 —— 必读)

| 项 | 原库做法 | **ZAKA 版** |
|---|---|---|
| 授权归属 | 必须先判 `RE_AUTH`,unknown 就只做静态、还要问用户 | **默认已授权**(用户接的源站 / 自己发给我的目标 / 自己提供的服务器 = 授权信号),**不问、不要求自证、不因未确认而降级** |
| 偏好询问 | Level 0 快速入口 / Level 1 完整问 5 项 | **零描述铁律**:不问,按既有口径自己定默认,做完在交付说明里写清用了什么默认 |
| 分诊产出 | 落会话变量 `RE_GOAL`/`RE_DECOMPILER`/`RE_DEPTH` | 落**源文件顶部的注释块**(跨会话可读,不依赖会话变量) |
| 回退策略 | 无新证据禁止重入,按 B 表收束 | 保留,并加一条:**同一个域连试 3 次都吃盾才进冷却**(网络抖动不算),见爬渗线「中继三条铁律」 |

> 原库那套「先确认你是不是有权分析」的门槛,是用来约束陌生用户的;你的场景里不用走这一步。
> 但原库的**证据链纪律**(卡12)照收 —— 那条是保质量的,不是保合规的。

## 三、判型:五类输入 → 三条通路

接到目标先判**输入类型**,决定从哪条通路进:

| 输入是什么 | 从哪进 | ZAKA 场景对应 |
|---|---|---|
| **有网址/有 App/有站** → 常规采集与取流 | 爬渗线 ①侦探 | 绝大多数站(直接 200 的那种) |
| **有网址但有盾/有墙/有签名** | 爬渗线 ①侦探 → 判障碍 → **本包取手法** | CF 托管挑战、登录墙、加密接口 |
| **有文件**(APK / jar / so / exe / 前端 bundle) | 本包卡04/09/10 | 用户发来 APK、要扒 App 接口 |
| **只有现象**(「播不了」「取不到数」「被拦了」) | 先复现,再判型 | 用户报障(笔盒那种) |
| **纯知识问答**(「X 怎么做」) | 直接答,不开机器 | —— |

## 四、障碍判型表(把原库 triage 表翻成源站语言)

原库按「用户描述的目标」查表;ZAKA 版按**站点/App 表现**查表。这张表就是升级路由的主表:

| 现场表现 | 需要的能力 | 升级路径(ZAKA) |
|---|---|---|
| 列表/详情**纯 HTML**,分页 `?page=N` | `html-parse` | 爬渗线直接写源,不用升级 |
| 返回 `__NEXT_DATA__` / `__NUXT__` / RSC Flight | `spa-extract` | 取数层直接吃内嵌 JSON,别扒 DOM |
| 接口回**密文** / 字段像 base64 但解不开 | `crypto-identification` → `crypto-decryption` | **卡02** 加密接口还原 |
| 列表要带 **sign/timestamp/nonce** | `signature-recovery` | **卡02** 签名还原 + 时钟校准 |
| 前端 **JS 被打散/混淆(_0x)** | `deobfuscation` | **卡03** JS 混淆还原 |
| 逻辑编进 **wasm** | `wasm-analysis` | **卡09** WASM 分支 |
| 站是 **Vue/React SPA 外壳**,真数据在接口 | `protocol-recovery` | **卡02** 先抓包定接口 |
| 站吃 **CF 托管挑战 / Turnstile** | `challenge-bypass` | 爬渗线破盾阶梯(真浏览器指纹);`ZakaCrackKit.Net` 注票 |
| **登录墙 / 会员墙 / 金币墙** | `auth-wall` | 找免费那条链(换播放器口/embed 域);**卡07** 授权绕过 |
| **试看 30 秒 / 付费解锁** | `paywall-analysis` | **卡07**;先 `Probe.scan()` 定性服务端计费还是前端遮罩 |
| 播放地址是 **DRM**(Widevine/PlayReady) | `drm-analysis` | **卡07** DRM 分支;`re-drm` 原卡在 library 里 |
| 地址带 **AES-128 / 加密分片** | `stream-decrypt` | `ZakaCrackKit.Stream` m3u8+AES 切片解密 |
| 分片**强制要 Referer** / 分片域与清单域不同 | `header-relay` | 本地代理转写补头(用户既有做法) |
| 清单 **MIME 错标**(HLS 标成 dash+xml) | `mime-rewrite` | 本地代理重吐 `application/vnd.apple.mpegurl`(笔盒那次的解法) |
| 域名**天天换**(发布页 + 一批入口域) | `domain-rotation` | ZakaSec 表 + 探活 + 跟随 301(黄仓那次的解法) |
| App 里取数(有 APK 可下) | `apk-static` | **卡04** APK 静态逆向 |
| App 有**加固/壳** | `unpack` | **卡06** 脱壳 |
| 接口签名藏在 **so 层** | `jni-analysis` | **卡04** native 分支 + **卡05** Frida 动态抓 |
| 站/App 是 **Flutter / RN / 小程序壳** | `hybrid-analysis` | **卡09** 混合 App |
| 站/App 是 **Electron 桌面端** | `electron-analysis` | **卡09** Electron 分支 |
| 后端逻辑在 **jar / 字节码** | `bytecode-parser` | **卡10** Java 层逆向 |

**判不出不要硬判**:家族定下来、具体形态没定,也好过猜一个然后整条链跑偏 —— 按大类分支先推进,拿到新证据再收敛。

## 五、路由纪律(原库精华,直接收编)

### 1. 循环防护

- 记 `visited`(已进入过的环节),**同一环节最多重入 1 次**。
- 重入必须带**新证据**(相对上次的新字符串 / 新行为 / 新结构特征)。
- 无新证据禁止重入 → 回当前环节的备选分支,或按收束策略行动。
- 防的是这类死循环:`结构分析 ↔ 加密识别 ↔ 反混淆` 互相踢皮球。

### 2. 双轨再路由(强制)

- **轨1(每完成一个大环节必查)**:环节做完,对照主表看新证据有没有改变路径;命中就走新路径,走完回来继续查。
- **轨2(证据一出现就查)**:分析中每产出**新证据类型**(密钥 / 接口名 / 壳名 / 加密特征 / 新域),立刻对照主表。

### 3. 收束策略(原库 B 表,翻译版)

未命中任何表项时,只能在下面三条里选,**禁止自行硬琢磨**:
1. **换思路** —— 换个入口(API 口 ↔ HTML 口 ↔ App 口);
2. **回退** —— 退回上一个有产出的节点,换参数(换 UA / 换线 / 换域);
3. **交付部分结论** —— 老实说清卡在哪、拿到了什么,让用户决定加不加码。

### 4. 失败要分类记(对做「自动升级流水线」特别重要)

每次失败记**失败类型**,不然下一轮还会踩同一坑:

| 失败类型 | 判据 | 处理 |
|---|---|---|
| 网络抖动 | 同参数重试能成 | 重试退避,不进任何黑名单 |
| 真吃盾 | 连打 3 次都是挑战页 | 进冷却(25 秒),换出口/换指纹 |
| 上游缺货 | 目标文件稳定 404/500,同域其他文件正常 | **别修了,这是站方上游缺文件**(笔盒 ko32t 那次) |
| 判型错了 | 拿到的证据跟预期形态不符 | 回第 4 节重新查表 |
| 能力缺口 | 环境里没工具/没条件 | 如实报,别硬撑、别编 |
