# 卡05 · 动态侧(插桩 / 脱壳 / 内存取证)

> 来源:`library/re-frida`、`re-frida-script-author`、`re-memdump`、`re-packer-id`、
> `re-unpack-simple`、`re-unpack-advanced`、`re-evasion`、`re-gdb`、`re-tracing`

**什么时候上动态**:静态全看完还是拿不到 → 密钥是运行时生成的 / 逻辑在壳里 /
加固 App / 要的答案只在内存里出现过一次。**动态是最后一张牌,但也是最准的一张。**

---

## 一、Frida 三件套(ZAKA 场景最常用)

### 1. spawn vs attach(选错就白干)

```bash
frida -U -f com.target.app          # spawn:从零启动 → 能抓启动期逻辑(解密/初始化)
frida -U com.target.app             # attach:附到已运行进程 → 快,但错过启动逻辑
```

**判据**:要抓的是「启动时才跑一次的初始化」(密钥装载、算法注册)→ 必须 spawn;
只是看看现状 → attach 就行。

### 2. 拿接口明文(App 取数最直接的一招)

```js
// hook / 打印 HTTP 全量请求与响应
Java.perform(function () {
  var OkHttpClient = Java.use("okhttp3.OkHttpClient");
  // 或者更省事:
  var Log = Java.use("android.util.Log");
  Log.i.overload('java.lang.String','java.lang.String').implementation = function(t, m) {
    console.log("[LOG] " + t + " :: " + m);   // 很多 App 自己就把接口打在 log 里
    return this.i(t, m);
  };
});
```

**更省事的路子(先试这个)**:
```bash
# 有的 App 直接日志里打接口 → logcat 就够
adb logcat | grep -iE "http|api|token|sign"
```

### 3. 改返回值 / 改参数(绕过校验)

```js
Java.perform(function () {
  var cls = Java.use("com.example.Target");
  cls.isVip.implementation = function () { return true; };       // 改返回值
  cls.checkSign.implementation = function (s) {                  // 看入参(偷签名算法)
    console.log("sign input:", s);
    return this.checkSign(s);
  };
});
```

原生层(so):
```js
Interceptor.attach(Process.getModuleByName("libfoo.so").findExportByName("getKey"), {
  onEnter: function (args) { console.log("arg0:", hexdump(args[0])); },
  onLeave: function (ret)  { console.log("ret :", hexdump(ret)); }
});
```

> ⚠️ Frida 17+ 里 `Module.findExportByName(null, ...)` 已移除 → 用 `Process.getModuleByName(...).findExportByName(...)`
> 或 `Module.findGlobalExportByName(...)`。

### 4. 枚举(不知道叫什么名字时)

```js
Java.perform(function () {
  Java.enumerateLoadedClasses({
    onMatch: function (c) { if (c.indexOf("target") >= 0) console.log(c); },
    onComplete: function () {}
  });
});
```
```js
Process.enumerateModules().forEach(m => console.log(m.name, m.base));
Process.getModuleByName("libfoo.so").enumerateExports().forEach(e => console.log(e.name));
```

### 5. 去 SSL Pinning(要抓 App 的 HTTPS 就得先过这关)

```js
// Android 通用模板:hook X509TrustManager,全信任
Java.perform(function () {
  var X509TrustManager = Java.use("javax.net.ssl.X509TrustManager");
  var TrustAll = Java.registerClass({
    name: "com.bypass.TrustAll",
    implements: [X509TrustManager],
    methods: { checkClientTrusted: function(){}, checkServerTrusted: function(){},
               getAcceptedIssuers: function(){ return []; } }
  });
  var SSLContext = Java.use("javax.net.ssl.SSLContext");
  SSLContext.init.implementation = function (km, tm, sr) {
    this.init(km, [TrustAll.$new()], sr);
  };
});
```
iOS:`hook SecTrustEvaluateWithError` 让返回值恒真。

**注意**:去 pin 之后还要看流量是否**加壳加密** —— 抓到了密文 ≠ 抓到了明文,那就回到卡02。

## 二、脱壳(加固 App / 带壳样本)

### 先识别(四要素组合判,别只看签名)

| 判据 | 壳特征 |
|---|---|
| **节名** | `.vmp0/.vmp1`(VMProtect)、`.themida`、异常节名;**只作线索不作依据**(壳会伪装成 `.text`) |
| **熵** | 高熵节(>7.0)且体积大 |
| **导入表** | 极小(只剩 `LoadLibrary`/`GetProcAddress`) |
| **入口点** | EP 指向非首节 / 指向壳 stub |

Android 侧对应特征:
- jadx 只见壳类:`com.stub.StubApp`(爱加密)、`com.secneo.apkwrapper`(梆梆)、`libjiagu.so`(360 加固)、`libDexHelper.so`(爱加密)
- `classes.dex` **体积异常小** → 真 dex 运行时解密

> **识别出壳名 ≠ 壳配置全开** —— 壳名只表示"加了什么壳",是否真的启用虚拟化/反调试是构建时选项。
> **先试常规流程**,确认真有 VM 分发型入口再投入高成本。

### 脱壳阶梯

1. **轻壳 / 压缩壳(UPX 类)**:`upx -d` 直接解 → **重识别一层**(可能壳套壳)
2. **普通加密壳**:断 `VirtualAlloc` → 单步到 OEP → dump + 修导入表
3. **强壳(VMProtect/Themida)**:别陷进 VM 字节码还原 —— **目标设成「降低复杂度」而不是「完全还原」**:
   - 把虚拟化区域标黑盒,**动态观察输入输出**(断 VM 入口,记参数与返回)
   - 只还原真正关键的那一小段(如校验逻辑)
   - 验收口径是「**可分析性**」,不是「还原度」
4. **Android 加固**:静态出不来 → **动态取内存 DEX**(Frida dump / 内存转储),或 `frida-dexdump` 类工具

### 反调试对抗(被踢时按层攻)

- 检测是**链式**的:过了一层才触发下一层 → **逐层攻**,别想一把梭
- 常见检测:调试端口 / 父进程名 / 窗口名(`FindWindowA`)/ **时间差** / 硬件断点寄存器(DR0-3)
- 对策顺序:隐藏调试器 → 改进程名 → **静态 patch 检测点再 attach** → 多线程壳先挂起监控线程
- **别信网上硬编码偏移** —— 版本一变就废,现场确认

## 三、内存转储(答案只在内存里的时候)

```bash
gcore <pid>              # 默认优先:整进程转储
# 或定向读:/proc/<pid>/maps 定址 → SIGSTOP → chunked pread
```

**两条铁律**(原库反复强调,踩了就白干):

1. **转储时机**:太早 = 壳还没解密(拿到的是密文);太晚 = 解密数据已被清掉。
   → **看到解密数据就立刻保存,先保存再继续**。
2. **`/proc/pid/mem` 不能无脑 open** —— 必须 maps 定址 + SIGSTOP + 分块读,否则偏移非法/权限报错。

其它:
- `[vsyscall]` / `[vdso]` 读失败是**预期行为**,别当 bug 排查
- `ptrace` 权限被拦 → root 跑,或临时放 `kernel.yama.ptrace_scope`

## 四、ZAKA 场景速查

| 要什么 | 走哪条 |

| App 接口的签名算法 | Frida hook 签名函数看入参(第 1.3 节) |
| 密钥运行时生成 | hook 加密函数**入参**,一次到手 |

## 五、常踩的坑

- **attach 晚了** → 启动期逻辑已经跑完,什么也没看到 → 改 spawn。
- **Frida 17+ 用旧 API** → `Module.findExportByName(null,...)` 报错,换 `findGlobalExportByName`。
- **改了 Java 层但没用** → 校验其实在 native(so),两个地方都要改。
- **多 ABI 混淆** → arm64 分析出的偏移套到 armeabi-v7a 全错;**以真机 ABI(arm64-v8a)为准**。
- **JNIEnv 当普通结构体看** → 它是**函数表指针**,所有 JNI API 都是表槽函数指针;Ghidra 里载入 `jni.h` 类型能自动还原。
- **so 里找不到 `Java_*` 导出** → 说明是动态注册(`RegisterNatives`),从 `JNI_OnLoad` 或 hook `RegisterNatives` 拿运行时注册表。
- **OLLVM 混淆的 native** → 平坦化走反混淆;字符串加密就 hook 解密函数读内存明文。
- **在沙箱外跑样本** → 一律沙箱/隔离环境,别在本机裸跑来路不明的样本。
